Analyse comparative : Vercel vs Cloudflare Pages

Les deux plateformes proposent un hébergement de sites statiques gratuit et performant. L'analyse ci-dessous est réalisée spécifiquement pour le cas d'Aurelia : un site vitrine Astro statique, sans backend, destiné à une clientèle professionnelle en Algérie et dans la région MENA.

▲

Vercel

8.5 / 10

✅ Points forts

  • ✓ Intégration GitHub/GitLab en 2 clics, déploiement automatique à chaque push
  • ✓ Preview deployments : chaque Pull Request génère une URL de prévisualisation
  • ✓ Interface très intuitive, parfaite pour démarrer rapidement
  • ✓ CDN mondial performant (Edge Network dans 100+ régions)
  • ✓ HTTPS automatique + certificat SSL gratuit
  • ✓ Support natif d'Astro (framework officiellement supporté)
  • ✓ Analytics basiques inclus dans le plan gratuit
  • ✓ Domaine personnalisé gratuit sur le plan Hobby

⚠️ Limites

  • △ Plan gratuit (Hobby) limité à usage non commercial selon les CGU — à vérifier pour un usage professionnel
  • △ 100 GB de bande passante/mois sur le plan gratuit
  • △ Le plan Pro coûte 20 $/mois pour usage commercial
  • ✗ CDN moins présent en Afrique du Nord que Cloudflare
  • ✗ Pas de protection DDoS avancée sur le plan gratuit
☁

Cloudflare Pages

9.2 / 10

✅ Points forts

  • ✓ Plan gratuit illimité en bande passante — aucune limite de trafic
  • ✓ Usage commercial autorisé sur le plan gratuit (contrairement à Vercel)
  • ✓ Réseau CDN Cloudflare : 300+ PoP dont plusieurs en Afrique & MENA (Johannesburg, Lagos, Le Caire, Marseille)
  • ✓ Protection DDoS intégrée et proxy Web Application Firewall (WAF)
  • ✓ HTTPS automatique + certificat SSL gratuit
  • ✓ Déploiement automatique depuis GitHub/GitLab
  • ✓ Web Analytics gratuit et sans cookies (RGPD friendly)
  • ✓ Domaine .pages.dev gratuit + domaine personnalisé
  • ✓ Temps de réponse excellent depuis l'Algérie et Afrique du Nord

⚠️ Limites

  • △ Interface légèrement plus complexe que Vercel pour les débutants
  • △ 500 builds/mois sur le plan gratuit (largement suffisant)
  • △ Preview deployments disponibles mais configuration un peu plus manuelle
  • ✗ Moins de documentation spécifique à Astro (bien que compatible)

🏆 Recommandation — Aurelia IT Services

Cloudflare Pages est le meilleur choix pour votre cas

Après analyse approfondie, Cloudflare Pages est la plateforme la plus adaptée au projet Aurelia pour ces raisons décisives :

  • Usage commercial autorisé gratuitement — votre site vitrine est un outil professionnel, Vercel l'interdit sur son plan gratuit.
  • Bande passante illimitée — aucun risque de surcoût si votre site génère du trafic.
  • Performance supérieure depuis l'Algérie et la région MENA — le réseau Cloudflare est très bien distribué en Afrique du Nord, garantissant une expérience rapide pour vos clients locaux.
  • Sécurité renforcée — protection DDoS, WAF et proxy SSL inclus gratuitement, ce qui est essentiel pour une entreprise IT qui veut inspirer confiance.
  • Analytics RGPD-friendly — sans cookies, parfait pour éviter les problèmes de conformité.

👉 Si vous débutez et souhaitez la démarche la plus simple possible, Vercel reste une excellente alternative — les étapes de déploiement sont identiques.

Configuration finale du projet pour la production

⚠️ Étapes obligatoires avant de pousser sur GitHub Effectuez ces modifications dans les fichiers du projet, puis faites votre premier commit.

Étape A — Mettre à jour l'URL du site dans astro.config.mjs

Ouvrez le fichier astro.config.mjs à la racine du projet et remplacez la valeur site par votre domaine réel :

// astro.config.mjs export default defineConfig({ site: 'https://VOTRE-DOMAINE.com', // ← Remplacez ici // Exemple : 'https://aurelia-it.com' // Si pas encore de domaine, utilisez votre URL Cloudflare : // 'https://aurelia-it.pages.dev' ... });

Étape B — Configurer Formspree pour le formulaire de contact

Dans src/components/ui/forms/ContactForm.astro et FooterForm.astro, remplacez VOTRE_FORMSPREE_ID par votre ID réel (voir Section 7 pour créer un compte Formspree).

<!-- ContactForm.astro — ligne action= --> action="https://formspree.io/f/VOTRE_FORMSPREE_ID" <!-- Exemple avec un vrai ID : --> action="https://formspree.io/f/xpznkwvr"

Étape C — Initialiser Git et créer le dépôt GitHub

Ouvrez un terminal dans le dossier du projet (datanova-1.0.0) et exécutez :

# 1. Initialiser git (si pas déjà fait) git init # 2. Ajouter tous les fichiers (en excluant node_modules et dist) git add . # 3. Premier commit git commit -m "feat: site vitrine Aurelia Automation & IT Services" # 4. Renommer la branche principale (si nécessaire) git branch -M main # 5. Connecter à GitHub (remplacez avec votre URL de repo) git remote add origin https://github.com/VOTRE-COMPTE/aurelia-it-services.git # 6. Pousser le code git push -u origin main
💡 Créer le repo GitHub Allez sur github.com/new, donnez un nom au repo (ex: aurelia-it-services), choisissez Private pour protéger votre code source, et copiez l'URL fournie.

Étape D — Vérifier le fichier .gitignore

Assurez-vous que le .gitignore exclut bien ces dossiers (le fichier d'origine est déjà correct) :

# .gitignore — vérifiez que ces lignes existent node_modules/ dist/ .env .env.local .data/

Guide déploiement — Cloudflare Pages Recommandé

✅ Durée estimée : 10-15 minutes Une fois le repo GitHub créé, le déploiement sur Cloudflare Pages prend moins de 15 minutes. Chaque push sur GitHub déclenche ensuite un redéploiement automatique.
1

Créer un compte Cloudflare

Rendez-vous sur dash.cloudflare.com/sign-up et créez un compte gratuit avec votre email professionnel. Aucune carte bancaire n'est requise pour le plan gratuit.

2

Accéder à Cloudflare Pages

Une fois connecté au dashboard Cloudflare, dans le menu de gauche, cliquez sur "Workers & Pages", puis sur "Pages", puis sur le bouton "Create a project".

3

Connecter votre dépôt GitHub

Choisissez "Connect to Git". Cloudflare va vous demander l'autorisation d'accéder à GitHub. Cliquez sur "Authorize Cloudflare Pages". Sélectionnez ensuite votre organisation/compte et choisissez le repo aurelia-it-services que vous avez créé.

💡 Accès limité Vous pouvez donner accès uniquement au repo spécifique (option "Only select repositories") pour plus de sécurité.
4

Configurer les paramètres de build

C'est l'étape la plus importante. Remplissez exactement comme ceci :

┌─────────────────────────────────────────────────┐ │ PARAMÈTRES DE BUILD — Cloudflare Pages │ └─────────────────────────────────────────────────┘ Project name : aurelia-it-services Production branch : main Framework preset : Astro ← sélectionnez dans la liste Build command : npm run build Build output directory: dist Root directory : datanova-1.0.0 ← IMPORTANT : votre dossier projet Node.js version : 20 (dans Environment variables)
⚠️ Root directory critique Si votre dépôt GitHub contient le dossier datanova-1.0.0 à la racine (et non directement les fichiers du projet), vous devez définir Root directory = datanova-1.0.0. Si vous avez mis les fichiers directement à la racine du repo, laissez ce champ vide.
5

Ajouter la variable d'environnement Node.js

Toujours dans la configuration de build, scrollez jusqu'à "Environment variables (advanced)" et ajoutez :

Variable name : NODE_VERSION Value : 20

Cela force Cloudflare à utiliser Node.js 20, compatible avec Astro 7.

6

Lancer le premier déploiement

Cliquez sur "Save and Deploy". Cloudflare va cloner votre repo, installer les dépendances et builder le site. Vous pouvez suivre les logs en temps réel. Le processus prend généralement 1 à 3 minutes.

7

Vérifier le déploiement

Une fois le build terminé, Cloudflare génère automatiquement une URL publique de type :

https://aurelia-it-services.pages.dev

Cliquez sur ce lien pour vérifier que toutes les pages s'affichent correctement : accueil, services, à propos, contact.

✅ C'est tout ! Désormais, chaque fois que vous poussez du code sur la branche main de GitHub, Cloudflare redéploie automatiquement votre site en 1-2 minutes.

Guide déploiement — Vercel Alternative

⚠️ Important — Licence Vercel Le plan gratuit "Hobby" de Vercel est réservé à un usage personnel non commercial. Pour un site d'entreprise comme Aurelia, le plan Pro à 20 $/mois est techniquement requis selon les CGU. Cloudflare Pages n'a pas cette restriction.
1

Créer un compte Vercel

Allez sur vercel.com/signup. Choisissez "Continue with GitHub" pour lier directement votre compte GitHub — c'est la méthode la plus rapide.

2

Importer le projet GitHub

Sur le dashboard Vercel, cliquez sur "Add New… → Project". Vercel liste vos repos GitHub. Sélectionnez aurelia-it-services et cliquez sur "Import".

3

Configurer le build

Vercel détecte automatiquement Astro. Vérifiez ou ajustez ces paramètres :

┌─────────────────────────────────────────────────┐ │ PARAMÈTRES DE BUILD — Vercel │ └─────────────────────────────────────────────────┘ Framework Preset : Astro ← auto-détecté Root Directory : datanova-1.0.0 ← si sous-dossier Build Command : npm run build Output Directory : dist Install Command : npm install --legacy-peer-deps
ℹ️ Install command Ajoutez --legacy-peer-deps à la commande d'installation car ce projet utilise des dépendances avec des peer deps croisées (React 19 + Svelte 5).
4

Déployer

Cliquez sur "Deploy". Vercel build et déploie en 1-2 minutes. Votre URL sera de type :

https://aurelia-it-services.vercel.app
5

Vérifier et tester

Parcourez toutes les pages du site depuis l'URL générée. Vérifiez les liens de navigation, les images, et que le formulaire de contact affiche correctement.

6

Connecter votre nom de domaine

Sur Cloudflare Pages

1

Accéder aux paramètres du projet

Dans Cloudflare Pages → votre projet → onglet "Custom domains" → cliquez "Set up a custom domain".

2

Entrer votre domaine

Saisissez votre domaine (ex: aurelia-it.com ou www.aurelia-it.com) et cliquez "Continue".

3

Configurer les DNS chez votre registrar

Cloudflare vous indique les enregistrements DNS à ajouter. Connectez-vous à votre registrar de domaine (ex: Namecheap, GoDaddy, OVH, etc.) et ajoutez :

# Si domaine racine (aurelia-it.com) Type : CNAME Name : @ (ou votre domaine) Value : aurelia-it-services.pages.dev # Si sous-domaine www (www.aurelia-it.com) Type : CNAME Name : www Value : aurelia-it-services.pages.dev
4

Attendre la propagation DNS

La propagation DNS peut prendre de quelques minutes à 48 heures. Cloudflare émettra automatiquement un certificat SSL une fois le domaine validé. Vous recevrez une confirmation par email.

💡 Astuce Si votre domaine est déjà géré par Cloudflare (nameservers Cloudflare), la propagation est quasi instantanée — c'est un avantage supplémentaire de Cloudflare Pages.

Sur Vercel

Dashboard Vercel → votre projet → Settings → Domains → entrez votre domaine → Vercel vous fournit les enregistrements DNS à configurer chez votre registrar (même procédure que ci-dessus, avec des valeurs différentes).

ℹ️ Mise à jour d'astro.config.mjs après ajout du domaine Une fois votre domaine configuré, mettez à jour astro.config.mjs avec votre URL définitive, puis faites un git push pour redéployer :
site: 'https://www.aurelia-it.com',
7

Activer le formulaire de contact (Formspree)

ℹ️ Pourquoi Formspree ? Le site est 100% statique — il n'y a pas de serveur backend. Formspree est un service qui reçoit les soumissions de formulaires et vous les envoie par email. Le plan gratuit inclut 50 soumissions/mois, largement suffisant pour un site vitrine.
1

Créer un compte Formspree

Allez sur formspree.io/register et créez un compte gratuit avec votre email contact@aurelia-it.com.

2

Créer un nouveau formulaire

Cliquez sur "+ New Form", donnez-lui le nom Contact Aurelia, puis sélectionnez l'email de destination. Formspree génère un ID unique de type :

https://formspree.io/f/xpznkwvr ← exemple d'ID
3

Mettre à jour les deux fichiers de formulaire

Remplacez VOTRE_FORMSPREE_ID par votre ID dans :

  • src/components/ui/forms/ContactForm.astro
  • src/components/ui/forms/FooterForm.astro
<!-- Exemple --> action="https://formspree.io/f/xpznkwvr" method="POST"
4

Pousser les changements et tester

git add src/components/ui/forms/ContactForm.astro git add src/components/ui/forms/FooterForm.astro git commit -m "fix: configure Formspree form IDs" git push

Après redéploiement automatique, testez le formulaire depuis votre site en ligne. Vous devriez recevoir un email de test dans la boîte Formspree.

Mettre à jour le site après déploiement

Workflow de mise à jour (modèle Git)

Le cycle de mise à jour est simple et entièrement automatisé :

# 1. Modifier vos fichiers dans src/ # ex: modifier le texte dans CTA.astro, ajouter une image, etc. # 2. Tester localement (optionnel mais recommandé) npm run dev # Lance le serveur local sur http://localhost:4321 # 3. Builder pour vérifier qu'il n'y a pas d'erreurs npm run build # 4. Commiter et pousser git add . git commit -m "update: modifier le texte de la section hero" git push # ✅ Cloudflare/Vercel détecte le push et redéploie automatiquement # Le site est mis à jour en ~1-2 minutes

📝 Modifications courantes

  • → Changer le texte : modifier directement le fichier .astro concerné
  • → Ajouter un service : éditer src/pages/services.astro
  • → Changer les coordonnées : Footer.astro + contact.astro
  • → Modifier les couleurs : src/assets/styles/global.css
  • → Remplacer une image : dans src/assets/images/

⚙️ Commandes utiles

  • → npm run dev — serveur de développement local
  • → npm run build — build de production
  • → npm run preview — prévisualiser le build
  • → npm run format:fix — formater le code

Résolution de problèmes courants

🔴 Erreur de build : "Cannot find module" ou dépendance manquante

Cause : Cloudflare/Vercel utilise npm install sans --legacy-peer-deps.

Solution : Dans les paramètres de build de la plateforme, remplacez la commande d'installation par :

npm install --legacy-peer-deps

🔴 Erreur de build : "Root directory not found"

Cause : Votre repo GitHub contient un sous-dossier datanova-1.0.0 mais le Root Directory n'est pas configuré.

Solution : Dans les paramètres du projet sur Cloudflare/Vercel, définissez Root Directory = datanova-1.0.0. Redéployez.

🟡 Les images ne s'affichent pas

Cause : Les images sont référencées avec des chemins incorrects.

Solution : Vérifiez que les images existent dans src/assets/images/. Après un npm run build, vérifiez que le dossier dist/_astro/ contient bien les fichiers image optimisés.

🟡 Le formulaire de contact ne fonctionne pas

Cause : L'ID Formspree n'a pas été remplacé ou n'est pas valide.

Solution :

  • Vérifiez que VOTRE_FORMSPREE_ID a bien été remplacé dans les deux fichiers de formulaire
  • Testez l'URL directement : https://formspree.io/f/VOTRE_ID
  • Assurez-vous que le domaine de votre site est autorisé dans les paramètres Formspree

🟡 Le domaine personnalisé ne fonctionne pas (erreur SSL ou 522)

Cause : La propagation DNS n'est pas terminée, ou les enregistrements sont incorrects.

Solution :

  • Attendez jusqu'à 48h pour la propagation DNS
  • Vérifiez la propagation sur whatsmydns.net
  • Si le domaine est chez un registrar algérien, la propagation peut prendre plus de temps

🟡 Erreur TypeScript lors du build : "astro:content not found"

Cause : Des références à l'ancien système de collections Keystatic peuvent subsister.

Solution : Vérifiez qu'aucun fichier n'importe depuis astro:content. Le fichier src/content.config.ts a été supprimé — si l'erreur persiste, vérifiez les imports dans les pages.
